## Key design decisions to carry forward

1. **`api_views.py` delegates to `views.py` handlers** — the shared handler functions (`estimate_get`, `estimate_put`, `estimate_delete`) live in `views.py` and are imported by both `views.py` endpoint classes AND `api_views.py`. This avoids duplicating access-control logic for two auth surfaces.

2. **`aggregation.py` is stdlib-only** — zero Django imports. This makes it fully unit-testable without a database (`test_aggregation_pure.py` runs in milliseconds). Only add this file if the feature has non-trivial pure-math logic worth isolating.

3. **`service.py` owns all ORM access** — views call `service.compute_<name>(...)` and catch typed exceptions; they never query the ORM directly. This separates HTTP and data-access layers.

4. **Integer cents for float-safe arithmetic** — workload converts hours to integer cents immediately on ingestion (100 cents = 1 hour) and back to float only at the API boundary. Copy this pattern for any feature that aggregates fractional numeric values and needs exact reconciliation.

5. **Row guard in service** — `if qs.count() > ROW_GUARD: raise WorkloadTooLarge()` before evaluating the queryset. Copy this pattern for any feature that can return unbounded result sets.
