## Key decisions made

- **Four different mapping rules**, because the ClickUp trees genuinely differ in depth.
  Do NOT unify them:
  - **cocos** — list → project, task → module, subtask → work item
  - **unity (teams)** — folder → project, **list → module**, task → work item
  - **marketing** — list → project, task → module, subtask → work item
  - **unity/TheOneFeature** — **sprint list → CYCLE** (the only cycles in the migration)
- **Estimates are leaf-only.** `workload_ext` rolls parent hours up from leaves; writing an
  estimate on a parent double-counts. Skipped parents are counted, never silently dropped.
- **Dates convert in +07**, not UTC, or tasks land a day early.
- **Cycle dates look off-by-one in raw UTC and are correct.** Plane's `convert_to_utc` stores
  project-timezone midnight as UTC. Do not "fix" this.
- **Unmapped assignees are left empty** for later backfill; the ClickUp id lives in `external_id`,
  so a re-run backfills without re-exporting.
- **Never create workspaces/users**; projects only with explicit approval (32 marketing + Dream Bit
  + TheOneFeature + HTML5). Two workspace memberships added, explicitly authorised.

### Verification lessons worth keeping

- **Verify totals per rule.** `modules + items == tasks` for cocos/marketing, but `items == tasks`
  for unity (its modules are *lists*, not tasks). Mixing these produced a false "MISMATCH".
- **Diff id sets against the previous snapshot** after a `--delta`; internal consistency only proves
  the file is well-formed, not that nothing was dropped. This caught mislabeled counts once.
- **Dry runs must exercise the write path.** The TOF loader's dry run reported 0 work items because
  `write_items` sat inside the non-dry branch.
- Silent data loss was caught twice this way (19 unity tasks, 10 cocos descendants).
