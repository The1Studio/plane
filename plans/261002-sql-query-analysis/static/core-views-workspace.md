## Top findings

1. **invite.py:270 — write amplification on invite accept.** One UPDATE per invitation inside the loop, followed by a `bulk_create` (invite.py:289) re-creating the same membership rows; batch both into one update and one create at most.
2. **base.py:292 — dashboard scans Issue 7 times per request** (4 counts + 3 aggregate scans) and then loads unbounded overdue/upcoming lists (base.py:319, base.py:327); one conditional aggregate plus sliced lists cuts the request to ~3 bounded queries.
3. **user.py:437 — profile stats repeats the same Issue scan 6+ times** (counts at user.py:437/448/459/471, subscriber count at user.py:483, distributions at user.py:400/416); combine into conditional aggregates on one base queryset.
4. **home.py:40 / user_preference.py:36 — per-key query + repeated bulk_create inside the preference-init loop.** Each missing key costs one SELECT and one re-running INSERT batch; fetch keys once and create once.
5. **invite.py:257 — N+1 on `invitation.workspace`** across the accept loop (invite.py:264/281/282/292): one Workspace query per invitation; a single `select_related("workspace")` removes it.
