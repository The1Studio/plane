## Top findings

1. **asset/v2.py:663 — list-comp N+1 over queryset** (`[self.save_project_cover(asset, project_id) for asset in assets]`). `save_project_cover` calls `Project.objects.get(id=project_id)` once per asset, all for the same project. Fix by hoisting the Project fetch (or single UPDATE) out of the loop.
2. **cycle/base.py:720-765 — six COUNTs in one endpoint.** `CycleProgressEndpoint.get` issues 6 separate `Issue.issue_objects.filter(...).count()` queries that differ only by `state__group`. Collapse into one `aggregate(total=..., backlog=..., unstarted=..., started=..., cancelled=..., completed=...)` with conditional Count filters.
3. **cycle/base.py:78,191,311,390,463 — Project re-fetched in every Cycle endpoint.** The same `Project.objects.get(id=project_id)` (and the timezone read) runs twice in `list`/`create`/`partial_update`/`retrieve` because `get_queryset()` already loaded it. Cache once per request via `self` or fetch only `timezone` with `.only()`.
4. **intake/base.py:178,269,337,506,552 — repeated `Intake.objects.filter(...).first()` + `Project.objects.get(pk=project_id)`** across intake viewset methods. Each is a per-request 1-row SELECT that could be memoized.
5. **external/base.py:174,197 — Workspace fetched twice in one GPT endpoint.** `Workspace.objects.filter(slug=slug).first()` runs, then later `Workspace.objects.get(slug=slug)` for serialization. Reuse the first instance.
