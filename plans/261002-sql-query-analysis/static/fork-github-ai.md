# SQL / ORM query anti-patterns — github_ext, ai_ext, clickup_migrate

**Coverage.** Read 90 `.py` files across three directories (73 production + 17 test):
`apps/api/plane/github_ext`, `apps/api/plane/ai_ext`, `apps/api/plane/clickup_migrate`.
Reviewed ~560 line-level ORM call sites from grep of `.objects.`, `.raw(`,
`connection.cursor`, `select_related`, `prefetch_related`, `.filter(`, `.count()`,
`.exists()`, `.all()`. All three scope dirs are fork-owned (github_ext, ai_ext,
clickup_migrate) — every row is **fork-safe: yes**. No raw SQL (`cursor()`)
outside one test; findings are pure ORM.

## Findings

| file:line | pattern | why it costs | suggested fix | fork-safe? |
|---|---|---|---|---|
| `apps/api/plane/clickup_migrate/management/commands/migrate_clickup.py:999` | `State.all_state_objects.filter(project=project, default=True).exists()` inside `for task in tasks_page:` loop | N+1: same exists() run for every task in a list; answer is constant per `(project, list)` | Hoist `has_default = ... .exists()` above the per-task loop; cache on the list-scope context | yes |
| `apps/api/plane/clickup_migrate/management/commands/migrate_clickup.py:351` | `User.objects.get(email__iexact=email)` inside `for member in members:` loop | N+1: one SELECT per ClickUp workspace member; hundreds of round-trips per run | Fetch `User.objects.filter(email__iexact__in=member_emails).values_list("email","id")` once and build an email→uid dict | yes |
| `apps/api/plane/clickup_migrate/management/commands/migrate_clickup.py:1073` | `MigrationCursor.objects.get_or_create(run=…, entity_type="comments", container_id=task_id, …)` inside per-task loop | N+1: one get_or_create per task | Pre-fetch existing cursors for the run once (`container_id__in=task_ids`), then `bulk_create(..., ignore_conflicts=True)` for missing rows | yes |
| `apps/api/plane/ai_ext/management/commands/ai_embed_backfill.py:208` | `AiEmbedding.objects.filter(entity_type=…, entity_id=…, chunk_idx=0, content_hash=…).exists()` inside `for row, embed_result in zip(...)` | N+1: one SELECT per entity; for an N-entity workspace = N exists() calls | One SELECT per entity_type per workspace: `existing = set(AiEmbedding.objects.filter(entity_type=… , entity_id__in=batch_ids, chunk_idx=0).values_list("entity_id", flat=True))`, then skip in Python | yes |
| `apps/api/plane/ai_ext/management/commands/ai_embed_backfill.py:213` | `AiEmbedding.objects.filter(entity_type=…, entity_id=…).delete()` per stale row | N+1: one DELETE per stale entity, one after another | Group stale entity_ids, then `AiEmbedding.objects.filter(entity_type=…, entity_id__in=stale_ids).delete()` in one statement | yes |
| `apps/api/plane/ai_ext/bgtasks/eval_task.py:64` | `AiEmbedding.objects.filter(workspace_id=…).values_list("entity_id", flat=True)` materialised to a `set` inside `for item in golden_set:` loop | N+1: every golden query re-fetches ALL workspace embeddings and rebuilds the set | Hoist the `all_entity_ids` set above the loop; the workspace's embedding corpus does not change between eval items | yes |
| `apps/api/plane/github_ext/views/config.py:159` | `State.objects.filter(project_id=project.id, name__iexact=value).exists()` inside `for key, value in rules_payload.items():` | N+1: one SELECT per rule key (DEFAULT_RULES = 3 keys → 3 SELECTs per project config PUT) | One SELECT: `existing = set(State.objects.filter(project_id=project.id).values_list("name__iexact", flat=True))`, then `value.lower() in existing` | yes |
| `apps/api/plane/ai_ext/views/search.py:298,309` | `_get_accessible_entity_ids` materialises tens of thousands of UUIDs into a Python `set`, then `_ann_search` / `_tsv_search` pass it as `entity_id__in=ids_list` to pgvector | Large IN clauses defeat pgvector HNSW (index is scanned, then re-filtered). Also loads every accessible Issue/Comment/Page/Cycle/Module/Project id into Python | Pass entity-type-scoped subqueries as the filter (`entity_id__in=Issue.issue_objects.filter(… access-filter …).values("id")`) so Postgres pushes the predicate into the scan | yes |
| `apps/api/plane/github_ext/services/state_transition.py:50,54,76` | `resolve_workspace_config` + `resolve_config` issue 3 sequential `StateTransitionConfig.objects.filter(scope="global"|"workspace"|"project")…first()` | 3 SELECTs per call instead of 1; `resolve_config` is called for every project on every PR transition | One SELECT with Q objects: `.filter(Q(scope="global") \| Q(scope="workspace", workspace_id=…) \| Q(scope="project", project_id=…))` and merge rows in Python | yes |
| `apps/api/plane/clickup_migrate/writers.py:233` | `for row in MappingTable.objects.filter(run=run, approved=True):` — unbounded `.filter()` over potentially large mapping table | Loads every approved mapping row into memory before the loop body starts; no iterator chunking | Use `.iterator(chunk_size=1000)` and build the three dicts in chunks, or `.values("kind","source_key","target_value").iterator()` to skip model hydration | yes |
| `apps/api/plane/ai_ext/management/commands/ai_embed_reconcile.py:50-61` | Six separate `set(Model.objects.filter(deleted_at__isnull=True).values_list("id", flat=True))` queries, then used as `entity_id__in=live_ids` | Loads all live Issue / Comment / Page / Cycle / Module / Project ids into Python memory; subsequent `exclude(entity_id__in=…)` also materialises | Replace each `set(...)` with a subquery: `qs.exclude(entity_id__in=Issue.issue_objects.filter(deleted_at__isnull=True).values("id"))` | yes |
| `apps/api/plane/github_ext/services/repo_map.py:31-34` | `Project.objects.filter(workspace=…).filter(Q(…))` then `candidates.count() == 1` then `candidates.first()` | Two SELECTs (COUNT(*) + SELECT *) on the same filter for a single-row existence check | Fetch once: `rows = list(candidates)` then `if len(rows) == 1: return rows[0]` (still loads rows but avoids the COUNT round-trip), or use `.aggregate(n=Count("id"))` | yes |
| `apps/api/plane/ai_ext/management/commands/ai_embed_backfill.py:58` and `ai_embed_reconcile.py:40` | `Workspace.objects.all()` and `AiEmbedding.objects.all()` — unbounded `.all()` on large tables | Loads every row (or every embedding) before the iteration; backfill loops over the result, reconcile filters it | `.iterator(chunk_size=…)` for the workspace list and for the AiEmbedding reconcile loop, plus a `deleted_at__isnull` style filter where appropriate | yes |

## Top findings (highest impact)

1. **`migrate_clickup.py:999` — State exists() per task.** The `has_default = State.all_state_objects.filter(default=True).exists()` call sits inside `for task in tasks_page:` even though the answer is identical for every task in a list. Hoisting it above the loop drops query count from `O(tasks)` to `O(1)` per list. Affects every ClickUp space; large runs hit thousands of redundant EXISTS queries.
2. **`migrate_clickup.py:351` — User lookup per member.** Resolving ClickUp workspace members one-by-one against `User` is the textbook N+1. Single batched `email__iexact__in=…` query turns hundreds of round-trips into one. Largest absolute win in raw query count.
3. **`ai_embed_backfill.py:208,213` — Two queries per entity, forever.** Each entity gets an `AiEmbedding.exists()` and, if stale, a `AiEmbedding.delete()` — both per row, both inside the same loop. Pre-fetching `entity_id → content_hash` once per entity_type reduces 2N queries to 2 per entity_type (and one bulk DELETE for stale rows).
4. **`ai_ext/views/search.py:298,309` — pgvector IN-clause blow-up.** Building a Python set of every accessible entity id and passing it to `_ann_search` / `_tsv_search` defeats pgvector's HNSW index. Subquery filtering (`entity_id__in=<type-scoped QuerySet>.values("id")`) is the access-aware fix; the current shape degrades sharply as accessible corpus grows.
5. **`eval_task.py:64` — full corpus fetch per eval item.** Re-fetching every `AiEmbedding.entity_id` for the workspace inside `for item in golden_set:` is unbounded N+1; the workspace embedding corpus is constant across eval items. Hoisting the set above the loop removes one query per golden-set row.
