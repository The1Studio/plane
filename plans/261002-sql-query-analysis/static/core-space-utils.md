## Top findings

1. **space/utils/grouper.py:66 - always-true annotation filter adds 3 M2M joins to every grouped public issue page.** The `or` condition can never exclude a key, so labels/assignees/issue_module ArrayAgg joins fan out rows on the hottest public endpoint; utils/grouper.py:71-73 has the correct `in {group_by, sub_group_by}` form and the Subquery-based (:49-73) equivalent.
2. **space/utils/grouper.py:111 / space/views/issue.py:653 - votes and reactions are loaded twice per request** (prefetch at issue.py:91-97 and :645-651, then again via `vote_items`/`reaction_items` ArrayAgg joins). Keeping one path halves that join cost.
3. **utils/porters/serializers/issue.py:76 and utils/exporters/schemas/issue.py:129 - export serialization is a guaranteed N+1**: ~10 relation queries per issue (plus nested FK chains and a per-row COUNT at exporters/schemas/issue.py:157). A 1k-issue export issues 10k+ queries.
4. **space/views/issue.py:238 - public comment lists N+1 on `actor` and `comment_reactions`** (serializer at space/serializer/issue.py:220,224); two small prefetch additions fix it.
5. **FK-descriptor fetch pattern (13 sites, e.g. space/views/issue.py:85, space/views/asset.py:144)** - every public endpoint pays +1 SELECT to load a Workspace/Project row whose id it already holds; `workspace_id=deploy_board.workspace_id` removes it everywhere.
